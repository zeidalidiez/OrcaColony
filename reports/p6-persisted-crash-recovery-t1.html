04 / What is and is not recovered

Proven

A tile-worker crash after forward can be recovered from coordinator-owned files, with exact replay, exact backward, one accepted update, and durable duplicate rejection.

Still open

The coordinator process and prefix autograd graph survive. This is not coordinator crash recovery, hostile manifest authentication, power-loss durability, network transport, or a refreshed-weight multi-step campaign.

The manifest is locally hashed in report evidence and validates owned tensor files before use, but it is not externally signed. Atomic file replacement plus fsync was exercised; directory-metadata durability across sudden power loss was not.

05 / P6 conclusion

Qualified for continued architecture work, not production

  • True boundary tiling preserves the full objective where P5 shallow blocks did not.
  • The matched T1 process control shows 50.10–50.11% lower worker peak RSS.
  • Persisted worker-loss recovery preserves exact optimizer/model authority.
  • Interactive boundaries and ~3 second cold replacement remain poor fits for high-latency ephemeral volunteers.
  • The coordinator still holds the canonical full model and prefix/suffix compute.
06 / Next method track

P7: sparse experts with more independent assignments

  1. Build a tiny deterministic sparse-expert tracer with coordinator-owned routing and shared trunk.
  2. Send one selected expert—not an interactive prefix/suffix stage—to each worker.
  3. Map expert gradients into one canonical AdamW update and compare against a centralized sparse control.
  4. Measure routing balance, per-worker residency/payload, inactive-expert staleness, and quality movement.
  5. Prefer the topology only if independence improves without recreating P5’s wrong local objective.
