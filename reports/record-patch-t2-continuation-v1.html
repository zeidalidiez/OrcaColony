JSON formatting improved. Record editing did not.

I continued the exact step-128 trajectory to step 512. The model learned to emit strict canonical JSON on 30 of 32 public cases, but it did not produce one correct patched record.

My finding: more exposure taught output form, not the usage scenario.

The language-selected step-512 checkpoint scored 0/32 exact and 0/32 semantic record matches. This result does not support even the narrow Record Patch task claim, and it says nothing about general intelligence.

What this evaluation measures

Record Patch v1 represents one practical operation: take a flat JSON record, apply ordered SET, DELETE, and RENAME instructions, then emit the exact canonical result. Exact match is intentionally strict because a missing field, wrong value, duplicate key, or unapplied operation makes a transformed record unusable.

This is not an input-copy failure or a formatting-only near miss. Most input fields and values were absent or replaced, and the requested operation was not integrated into a preserved record.

What training did

  • It lowered public transcript language loss at every continuation milestone.
  • It moved generation from duplicate-key objects to mostly strict canonical JSON.
  • It increased teacher-forced answer-token accuracy from 40.7% to 45.0%.
  • It reduced continuation clipping pressure: 141 of 384 updates clipped, versus 114 of the first 128.

It did not produce an exact or semantically correct record, preserve the input record reliably, or show one complete answer under teacher forcing. The observed pattern supports “syntax before task conditioning” as a description. It does not by itself prove why the task failed.

The complete trajectory consumed 2,048 of 4,618 packed sequences and 1,048,576 of 2,364,891 packed token positions. No public prompt or target appeared exactly among the 32,768 generated training examples, and no nearest same-bucket target was equal. Character similarity to the nearest same-bucket training prompt ranged from 0.7181 to 0.8641; this surface comparison is not a semantic contamination test.

The official process used one CPU thread, 1,590,751,232 bytes peak RSS, zero swap, and 1,914.7 seconds before checksum packaging. All 23 retained run files passed their checksum manifest.

Historical follow-up hypothesis

At the time of analysis, I proposed an answer-only causal loss comparison from the same initialization as one way to isolate whether prompt-token loss consumed too much of the small training budget. That was an agent hypothesis about this experiment, not a decision about OrcaColony's next campaign.

A future campaign owner may choose that comparison, choose a different experiment, or leave Record Patch closed. The framework does not make that choice.
