Report 001Early feasibility · not promoted

Partial workers lower peak residency, but complete coverage still moves the whole model.

A four-step T0 experiment proved that one selected transformer block can train in an executable shallow worker and map a real gradient back into a coordinator-owned full model. The approach reduced worker tensor residency by 44.96% and per-assignment payload by 44.59%, but delivered only 38.02% of the full-model baseline's loss improvement and did not reduce unique model bytes across complete block coverage.

Promising mechanism, unresolved training method.

The slice advances P5 because it demonstrates real mapped updates and a material peak-memory reduction. It does not yet establish useful partial-model training, persistent transfer savings, or practical language-model quality.

Decision Continue to T1 held-out testing and shared-state reuse. Do not promote the topology.
01 / Question

Can a worker train one rotating block without holding the complete coordinator model?

The coordinator retained a four-block, 1,334,016-parameter model. Each assignment copied shared token/position/output components plus one selected transformer block into a shallow executable worker. Only that block was trainable. Its named gradients were mapped into the corresponding coordinator block, and coordinator-owned AdamW applied the update.

The selected sequence was blocks 0, 1, 2, 3, one update per block, against the deterministic T0 fixture. A replicated full-model run used the same four batches and optimizer settings as the control.

The key negative finding The worker payload contains 2,163,712 bytes of shared state plus a 793,088-byte selected block. Once one persistent worker has rotated through all four blocks, its unique tensors total 5,336,064 bytes—exactly the full model payload. This lowers peak residency, not unique transfer across complete coverage.
03 / Findings

What worked, and what needs to change.

  • +
    Real partial updates reached the canonical model.

    Every selected block produced a complete 793,088-byte gradient that mapped by exact parameter name into the coordinator-owned model.

  • +
    Peak worker tensor residency fell by 44.96%.

    The worker executed forward and backward with 2.97 MB of resident tensors instead of 5.40 MB for the full T0 model.

  • −
    Shared embeddings and output state dominate the worker.

    Only 198,272 of 739,200 worker parameters were trainable. Width/vocabulary reduction or persistent shared-state reuse is needed for a stronger memory/transfer result.

  • −
    The shallow-submodel objective is not the full-model objective.

    Four rolling updates recovered 38.02% of the control's loss improvement. A selected block's shallow-model gradient is not the corresponding slice of the full-model gradient.

04 / Boundaries

This is systems evidence, not useful-model evidence.

The T0 fixture is deterministic and synthetic. Mean-loss movement proves that the mapped updates changed the optimization trajectory in the expected direction; it does not show better stories, extraction, reasoning, or any other practical behavior.

The experiment used one Windows CPU process, equal-size blocks, no volunteer network, no retry, no persisted worker cache, and no held-out real-data evaluation. Process RSS and runtime were not measured in this first slice; tensor residency is not the same as total process memory.

05 / Next iteration

Test T1 quality and reuse without blocking later method work.

The next P5 method slice should run the same block rotation on authenticated T1 TinyStories data, evaluate a frozen holdout, and explicitly cache shared worker state so per-round transfer reflects only newly selected blocks. It should compare checkpoint trajectories—not just the final number—with replicated full-model training.

Practical campaigns are owner-directed and independent of P5, P6, or P7 implementation. No practical task, data, rubric, or campaign was selected by this systems study.
