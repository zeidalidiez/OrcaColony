04 / Timing boundary

No end-to-end speed claim

Measured full worker

Full child compute was 332.68–368.88 ms and its input/gradient IPC round trip was 367.71–416.72 ms.

Not directly comparable

The tile report measures worker compute and IPC phases, but coordinator prefix, suffix, input-adjoint backpropagation, clipping, and optimizer work sit outside those timers. A lower tile IPC time is not an end-to-end speedup.

Cold initialization was similar: 2.90–3.23 s for the tile and 3.06–3.24 s for the full worker. Persistence remains required for both.

05 / What this proves

Worker-memory feasibility passes; larger goals remain open

  • A real child process can hold only one T1 block and still contribute exact full-objective gradients.
  • Under a matched runtime, the tile cuts isolated worker peak RSS roughly in half.
  • The coordinator still retains the full model and performs true prefix/suffix computation.
  • The result is trusted-local and same-checkpoint; no network, refreshed weights, retry, hostile input, or larger-than-coordinator proof.
  • ~332 MB remains a real worker requirement for this Python/PyTorch implementation despite 3.16 MB of weights.
06 / Next bounded experiment

Crash after forward; recover exactly on a replacement tile

  1. Persist checkpoint, dataset cursor, tile identity, phase, and owned prefix-activation bytes before dispatch.
  2. Accept and hash the forward output, then terminate the first worker before backward.
  3. Spawn a replacement, replay the same immutable tile/input, and require byte-identical output before sending the persisted adjoint.
  4. Accept one exact gradient result, reject duplicates, map once, and reproduce centralized AdamW state.
  5. Measure recovery latency, retransmitted bytes, and retained coordinator state.
