OrcaColony / Report 003 / P5 conclusion

Sharding every block fixes update coverage—not the objective.

Six block-affine workers lowered held-out loss 82.78% more than sequential rotation and kept each worker below full-model exposure. But progress reached only 39.28% of the full control, nearly stopped after step 8, and required unfavorable colony-wide aggregate resources.

P5 concluded · not promoted Campaign: orcacolony-t1-tinystories-smoke-v1 12 global steps · 72 assignments Recorded: 2026-07-25
Decision
Close direct shallow block training as a negative P5 result. Carry its per-worker memory lesson into P6, where tiled execution must preserve the model's true activation and gradient boundaries.
01

Did normalizing block update coverage close the quality gap?

It closed part of it, then plateaued. Each global step used one worker for every block against one coordinator snapshot and one training batch. The coordinator mapped all six gradients, clipped the combined block gradient, and performed one AdamW step. Every block's live optimizer state reached exactly step 12; frozen shared tensors acquired no optimizer state.

    No individual worker receives every block.

    Affinity keeps one worker's unique parameter-position exposure at its shared path plus one block, unlike a single rotating worker that cumulatively covers the full model.

  • !
    Cold start duplicates 8,652,800 shared bytes six times.

    The first global step downloads 2.57 full-model equivalents across the colony. Opportunistic churn would repeatedly pay this cost.

  • !
    The CPU simulator does not prove distributed speedup.

    Six workers execute serially in one process: sharded training took 12.004–12.016 seconds versus 5.891–5.935 seconds for the full control. Parallel critical path, networking, stragglers, and retries remain unmeasured.

03

Why P5 closes without promotion.

Report 002 showed that sequential rotation unfairly updates one block where the control updates the whole model. This experiment removed that schedule mismatch for all six blocks. Quality improved substantially, so schedule coverage was a real problem—but the new plateau demonstrates that it was not the only problem.

  • !
    Each block still solves the wrong local task.

    The shallow worker receives token embeddings directly and predicts through the shared output path directly. It does not receive the selected block's true prefix activation or downstream gradient from the full stack.

  • !
    Shared embeddings, position embeddings, and final normalization stay frozen.

    The exact shared SHA-256 remained unchanged and zero shared parameters acquired AdamW state, while the full control trained them.

  • →
    The negative result is useful.

    It rejects “just dispatch every shallow block” before a connected protocol, larger model, or volunteer campaign makes the same mistake more expensive.

P5 conclusion: shallow block workers are a valid memory-reduction mechanism and an invalid quality-preserving training method under the tested objective. Do not promote this topology into supported campaigns.
04

P6 starts with exact boundary-preserving tiled execution.

  1. Preserve the full-model objective. A tile receives its true input activation and returns an output/gradient boundary so prefixes and suffixes remain part of the same computation graph.
  2. Prove one-step numerical parity first. Compare every mapped parameter gradient and post-AdamW tensor with centralized FP32 before measuring scale.
  3. Account for activation traffic. Report per-tile model bytes, activation/adjoint bytes, individual residency, colony totals, cold/warm transfer, and recomputation.
  4. Then test held-out trajectories. Only after exact local parity should T1 compare tiled and centralized checkpoint paths.

This moves from an independent shallow surrogate objective to distributed execution of the actual objective. It may reduce memory without reducing aggregate compute or transfer; P6 must measure that tradeoff rather than assume it.

05

Evidence boundary and reproduction

This is a CPU FP32 feasibility experiment on a randomly initialized 6.9M-parameter decoder, 12 training batches, and 16 held-out TinyStories sequences. Six workers are simulated serially in one process. Combined-process peak RSS was 797,249,536–801,521,664 bytes and includes coordinator, baseline, six worker sessions, optimizers, and dataset tensors. It is not individual-worker RSS or connected-network evidence.

Two isolated runs matched every deterministic field exactly: all seven loss pairs, 72-assignment order, six block optimizer trajectories, shared-state identity, model hashes, and byte accounting. Only timing and process RSS varied.
