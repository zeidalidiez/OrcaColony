Exact IPC is cheap. Process memory and cold startup are not.

A persistent spawned worker executed T1 block 2 for two different authenticated batches with one model transmission. Every raw gradient, clipped gradient, AdamW tensor, and updated model tensor matched the centralized reference exactly.

What worked

The child never loaded a full model, retained one immutable block for a warm second batch, returned exact gradients, and terminated with exit code 0.

What remains unknown

There is no matched full-model child measurement yet. The 331.6 MB peak includes Python, PyTorch, allocator, autograd, and serialization state and must not be compared directly with the 28.0 MB full-model tensor count.

05 / Boundary of evidence

This is not a production worker launcher

  • Trusted local Python child using multiprocessing spawn; no sandbox, Job Object, restricted token, or environment scrubbing.
  • Two assignments share one immutable checkpoint. This does not yet prove refreshed weights between optimizer steps.
  • A stalled child before model read now times out cleanly with no live child; there is still no sandbox, hostile-payload safety, or remote transport claim.
  • Application bytes exclude multiprocessing’s private framing.
  • The coordinator still owns and retains the full model and performs prefix/suffix execution.
06 / Next bounded experiment

Measure the matched full-process control before retry engineering

  1. Launch a full-model child through the same spawn lifecycle and run the same two T1 cursors.
  2. Measure startup, current/peak RSS, tensor/control bytes, and forward/backward latency under the identical harness.
  3. Compare tile versus full process on real peak memory—not tensor counts.
  4. If the tile still provides useful resident-memory reduction, add persisted boundary transactions and crash/retry.
