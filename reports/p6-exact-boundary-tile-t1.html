04

Timing remains local parity evidence.

Across both sweeps, centralized steps took 0.358–0.417 seconds and tiled steps took 0.360–0.391 seconds. The ranges overlap, and no process serialization, IPC/network transport, queueing, or retry delay exists. No speedup is claimed.

Combined-process peak RSS ranged from 1,059,287,040 to 1,090,740,224 bytes as repeated models and optimizer allocations raised the process high-water mark. That is neither worker-only memory nor a per-block peak.

The next measurement must use process boundaries. In-process tensor accounting has now done its job: it proved exactness and supplied a byte contract. Repeating more local blocks would not answer the remaining worker-memory or reliability questions.
05

Next P6 slice: an authenticated persistent tile process.

  1. Spawn a separate worker process. Load one exact block from authenticated bytes and report isolated cold and warm RSS.
  2. Serialize every boundary. Measure actual wire-format sizes for input activation, output activation, output adjoint, input adjoint, and block gradients.
  3. Keep the tile warm. Reuse authenticated block weights for a second assignment and prove identical results without retransmitting them.
  4. Measure critical path and failure states. Record forward and backward latency separately, then persist enough coordinator boundary state to retry after a worker exits.

Only after that connected local proof should P6 expand to multiple tiles or volunteer-facing scheduling.

06

Evidence boundary and reproduction

This report covers one authenticated T1 training batch, six independent one-step block substitutions, CPU FP32, and local in-process boundaries. It proves every block location can reproduce the centralized authority and measures tensor transfer; it does not prove connected execution, restart, or held-out campaign trajectories.
