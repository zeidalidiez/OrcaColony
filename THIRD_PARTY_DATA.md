# Third-party data

## TinyStories

OrcaColony's T1 artifact builder can derive a bounded training and validation subset from [`roneneldan/TinyStories`](https://huggingface.co/datasets/roneneldan/TinyStories).

- Pinned repository revision: `f54c09fd23315a6f9c86f9dc80f725de7d8f9c64`
- Declared dataset license: [CDLA-Sharing-1.0](https://cdla.dev/sharing-1-0/)
- Dataset card: <https://huggingface.co/datasets/roneneldan/TinyStories>
- Training source file SHA-256: `c5cf5e22ff13614e830afbe61a99fbcbe8bcb7dd72252b989fa1117a368d401f`
- Validation source file SHA-256: `94e431816c4cce81ff71e4408ff8d3bda9a42e8d2663986697c3954288cb38b4`

The source dataset consists of stories synthetically generated by GPT-3.5 and GPT-4. The default OrcaColony build downloads fixed byte prefixes from the pinned revision, trims each prefix to its last complete `<|endoftext|>` story, trains a byte-level BPE tokenizer, and records all subset and artifact hashes in `manifest.json`.

If packed data is redistributed, preserve its generated `DATASET-NOTICE.md`, this source attribution, and the CDLA-Sharing-1.0 terms. Model checkpoints are intended to qualify as computational Results only when they do not include more than a de minimis portion of the source Data.
